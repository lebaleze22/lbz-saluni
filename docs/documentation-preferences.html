SALUNI / Working preference

Documentation in HTML

Recorded on 8 September 2026, at the user's request.

Produce requested document files in HTML (.html) by default. Do not create Markdown (.md) deliverables.

Applies to

Reports, checkpoint reports, details, summaries, drafts, schemas, diagrams, plans, specifications, guides, and similar written deliverables.

Delivery conventions

  • Provide a direct link to the finished HTML file.
  • Use UTF-8, clear navigation for long documents, readable tables, and responsive layouts.
  • Prefer a standalone file with embedded styles and no network dependency for reading it.
  • Include a date, scope, and source references where they help the reader assess a report.
  • Use HTML and inline SVG or CSS for document diagrams when suitable.
  • Follow an explicit request for a different format when one is given.

Project scope

Feature workflow

Before implementing a new feature, describe its proposed scope and wait for the user's agreement. Once that scope is approved, implement, test, and update the local running app. Do not start a different feature without presenting it first.

This preference governs documentation deliverables. Application source, executable schemas such as prisma/schema.prisma, and tool configuration keep their required file formats. Existing documents and the application's PDF/Excel export features were not migrated by this preference update.

This file records the preference within this repository. It does not change global assistant settings.
