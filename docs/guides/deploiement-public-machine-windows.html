SALUNI · Test deployment · Windows

Host SALUNI publicly and continue development safely

This guide installs the stable client-deployment branch in a separate directory. Docker keeps that deployed snapshot running while unfinished features are developed in the original repository.

The deployment is self-contained: PostgreSQL, authentication, SALUNI, nginx, and the public HTTPS tunnel all run on your machine. No Supabase Cloud project is required.

1. How deployment and development stay separate

C:\SALUNI\server client-deployment The public test installation. Update it only with reviewed deployment commits.

Editing files in the development directory does not alter the running Docker image. The public test changes only when you intentionally update and rebuild the server directory.

2. Requirements

  • Windows 10 or Windows 11 with current updates.
  • Git installed and available in PowerShell.
  • Docker Desktop installed, started, and configured to use Linux containers.
  • An Internet connection that remains available while people test SALUNI.
  • The machine configured not to sleep while acting as the server.
  • At least 4 GB of free memory and adequate disk space for images and database backups.

Verify the two required commands in PowerShell: 

git --version
docker info

3. First installation

3.1 Create a dedicated server checkout

Run PowerShell as your normal Windows user:

New-Item -ItemType Directory -Force C:\SALUNI
Set-Location C:\SALUNI

git clone --branch client-deployment --single-branch `
  https://github.com/lebaleze22/lbz-saluni.git server

Set-Location C:\SALUNI\server

If the GitHub repository is private, Git will request your GitHub credentials or personal access token during cloning.

3.2 Run the installer

powershell -ExecutionPolicy Bypass `
  -File scripts/server/install-windows.ps1

The installer performs the following actions:

  1. Generates strong PostgreSQL, runtime-role, and authentication secrets.
  2. Writes the secrets to the ignored .env.server file.
  3. Builds SALUNI from the checked-out deployment source.
  4. Starts PostgreSQL and the local authentication service.
  5. Applies the Prisma migrations and configures the restricted database role.
  6. Starts SALUNI, nginx, and Cloudflare Tunnel.
  7. Asks for the salon name and first Owner account.
  8. Imports the initial catalogue and verifies the installation.
  9. Prints the public HTTPS login address.

Keep .env.server private. It contains database and authentication secrets. It is excluded by Git and must never be sent by email or committed.

4. Open and share the public application

The installer prints an address similar to:

https://random-words.trycloudflare.com/login

To retrieve it later:

Set-Location C:\SALUNI\server

docker compose --env-file .env.server `
  -f docker-compose.server.yml `
  logs cloudflared | Select-String "trycloudflare.com"

The application is publicly reachable by anyone who has this URL. Authentication still requires a valid SALUNI account. Only the Owner can create Director or staff accounts.

A Quick Tunnel is intended for testing. Its generated hostname can change if the tunnel container is recreated. A domain and named Cloudflare Tunnel will provide a permanent address later.

5. Daily operations

Check service status

Set-Location C:\SALUNI\server

docker compose --env-file .env.server `
  -f docker-compose.server.yml ps

View recent logs

docker compose --env-file .env.server `
  -f docker-compose.server.yml `
  logs --tail 200 core-api nginx gotrue cloudflared

Stop the test server

docker compose --env-file .env.server `
  -f docker-compose.server.yml stop

Start it again

docker compose --env-file .env.server `
  -f docker-compose.server.yml up -d

After restarting the tunnel, retrieve the current public URL from its logs before sharing it. Docker restart policies restart the services automatically after Docker Desktop starts.

6. Continue working on remaining features

Use the original development directory, not C:\SALUNI\server.

Set-Location "C:\Users\LeBaleze\Documents\Personal\MyApps\lbz_Saluni"

git switch whatsapp-development-20260914
git status

Future work remains on development branches. When a group of changes is ready for public testing, review it, run the full checks, and copy only the approved changes into client-deployment. The server does not update automatically.

7. Deploy an approved update

After the approved changes have been pushed to client-deployment:

Set-Location C:\SALUNI\server

git pull --ff-only origin client-deployment

powershell -ExecutionPolicy Bypass `
  -File scripts/server/install-windows.ps1 `
  -SkipInitialization

The update preserves .env.server and the PostgreSQL Docker volume, applies new migrations, rebuilds the application, and prints the current public URL. The -SkipInitialization option prevents the installer from asking for or recreating the first Owner.

8. Back up the database

Create a directory outside the Git repository and produce a PostgreSQL dump:

New-Item -ItemType Directory -Force C:\SALUNI\backups
Set-Location C:\SALUNI\server

docker compose --env-file .env.server `
  -f docker-compose.server.yml `
  exec -T postgres pg_dump -U postgres -d postgres -Fc `
  -f /tmp/saluni-backup.dump

$stamp = Get-Date -Format "yyyyMMdd-HHmmss"
docker cp saluni-server-postgres:/tmp/saluni-backup.dump `
  "C:\SALUNI\backups\saluni-$stamp.dump"

Keep at least one additional encrypted copy on another disk. A Docker volume protects data across normal container rebuilds, but it does not replace an external backup.

9. Troubleshooting

Problem Action
Docker Desktop is not running Start Docker Desktop, wait until the engine is ready, and rerun the installer.
Port 8080 is already occupied Change SALUNI_HTTP_PORT in .env.server, then rerun with -SkipInitialization.
No public URL appears Inspect docker compose --env-file .env.server -f docker-compose.server.yml logs cloudflared and verify Internet access.
The public URL shows a gateway error Check docker compose --env-file .env.server -f docker-compose.server.yml ps, then inspect the core-api, nginx, and gotrue logs.
The site disappears when the machine is idle Disable Windows sleep while plugged in and enable Docker Desktop startup at sign-in.

10. Current test boundary

  • The public test runs only the code committed to client-deployment.
  • The unfinished messaging integration is absent from the deployed branch.
  • The Quick Tunnel provides a temporary public address and no availability guarantee.
  • The server is available only while the Windows machine, Internet, and Docker are running.
  • A permanent domain, named tunnel, monitoring, and automated off-machine backups belong to the production-hardening stage.
